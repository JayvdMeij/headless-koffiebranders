# Spaarne Koffiebranders

A fast, accessible headless website for **Spaarne Koffiebranders**, a fictional specialty coffee roastery in Haarlem. Content is managed in Sanity, the site is statically generated with Nuxt 3, and it is hosted on Netlify.

The site ships **zero client-side JavaScript**: every page is prerendered HTML with inlined critical CSS, self-hosted fonts and responsive images from the Sanity CDN.

## Stack

| Concern | Choice |
| --- | --- |
| Framework | [Nuxt 3](https://nuxt.com) (3.21) with TypeScript (strict) |
| CMS | [Sanity](https://www.sanity.io) Studio v6 in `/studio`, queried with `@sanity/client` and GROQ |
| Types | Sanity TypeGen: query results are typed from the schema (`types/sanity.types.ts`) |
| Images | `@nuxt/image` Sanity provider: `srcset` with fixed widths, hotspot cropping, `auto=format` (AVIF/WebP) |
| Fonts | `@nuxt/fonts`: Inter and Fraunces downloaded at build time and served from the site itself (woff2, Latin subset, metric-matched fallbacks) |
| SEO | `useSeoMeta` per page, canonical URLs, Open Graph/Twitter cards, JSON-LD, `@nuxtjs/sitemap`, `@nuxtjs/robots` |
| Forms | Netlify Forms (no JavaScript, honeypot spam protection) |
| Hosting | Netlify, static output with generated security headers |
| Quality | ESLint (`@nuxt/eslint`), `vue-tsc`, Lighthouse and axe-core scripts |

## Getting started

Requirements: Node.js 20 or newer (22 recommended).

```bash
npm install
cp .env.example .env   # optional: defaults point to the demo Sanity project
npm run dev            # http://localhost:3000
```

### Sanity Studio

```bash
cd studio
npm install
npm run dev            # http://localhost:3333
```

The Studio has singletons for **Site settings**, **Home**, **Over ons**, **Koffie (overview)** and **Contact**, plus a **Coffees** collection. Every image requires alt text.

To fill an **empty** dataset with the demo content (photos from Unsplash):

```bash
cd studio
npm run seed
```

The seed creates the coffee documents with Sanity-generated IDs. Running it twice duplicates the coffees, so run it once per dataset.

After changing schemas or queries, regenerate the types:

```bash
npm run typegen
```

To deploy the Studio to `spaarne-koffiebranders.sanity.studio`, run `npm run deploy` in `/studio`.

## Performance

- **Static generation.** All routes are prerendered. The coffee slugs come from Sanity in the `nitro:config` hook, so detail pages are generated even when nothing links to them yet.
- **No client JavaScript.** `features.noScripts` removes the Vue runtime. A Nitro plugin strips leftover inline bootstrap scripts (JSON-LD is kept). Navigation, the layout and the form all work natively.
- **Critical CSS inlined**, with small per-component stylesheets.
- **Images.** `SanityImage` renders `<img>` with explicit `width`/`height` (no layout shift), a `srcset` from 320 to 2000 px and accurate `sizes`, and lazy loading below the fold. The LCP image uses `fetchpriority="high"` and a responsive `<link rel="preload">`. The Sanity CDN picks AVIF or WebP per browser.
- **Fonts.** Two woff2 files, self-hosted under `/_nuxt/fonts` and preloaded, with `font-display: swap` and size-adjusted fallback faces so the swap causes no layout shift.
- **Caching.** Hashed assets in `/_nuxt/*` are served with `Cache-Control: immutable` for one year.

## Accessibility (WCAG 2.1 AA)

- Semantic landmarks, one `h1` per page and a logical heading order. There is a skip link to `main`, and `aria-current` marks the active navigation item.
- All colour pairs meet a contrast ratio of 4.5:1 or higher. Focus styles are clearly visible.
- Coffee cards use one stretched link, so each card is a single tab stop with a readable name.
- Form fields have visible labels, `autocomplete`, hints through `aria-describedby`, and native validation.
- Alt text is required in the CMS. Breadcrumbs, opening hours (`<dl>`) and the address (`<address>`) use the matching HTML elements.
- The layout reflows at 320 px without horizontal scrolling, and `prefers-reduced-motion` is respected.

## SEO

- `usePageSeo` sets the title template, meta description, canonical URL, Open Graph and Twitter tags. The sharing image is a 1200×630 crop from Sanity: the page's own SEO image, else the page image, else the site default.
- JSON-LD: `CafeOrCoffeeShop` (home and contact), `ItemList` (overview), `Product` + `BreadcrumbList` (coffee detail).
- `sitemap.xml` and `robots.txt` are generated at build time. The thank-you and not-found pages are `noindex` and left out of the sitemap.

## Security

`scripts/security-headers.mjs` writes Netlify's `_headers` file after every build:

```
Content-Security-Policy: default-src 'none'; script-src 'none';
  style-src 'self' 'sha256-…' (one hash per inlined <style> block);
  img-src 'self' https://cdn.sanity.io; connect-src 'self'; font-src 'self';
  form-action 'self'; frame-ancestors 'none'; base-uri 'none'; upgrade-insecure-requests
Strict-Transport-Security: max-age=63072000; includeSubDomains; preload
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=(), usb=(), browsing-topics=()
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Resource-Policy: same-origin
```

The CSP has no `unsafe-inline`. Instead, the script hashes every inline style block in the generated HTML. The build **fails** if any page contains an executable `<script>`, an inline `style` attribute or an inline event handler, so a change cannot weaken the policy unnoticed.

## Deploying to Netlify

1. Create a new site from this repository. `netlify.toml` already sets the build command (`npm run generate`), the publish directory (`.output/public`) and Node 22.
2. Set `NUXT_PUBLIC_SITE_URL` to the final domain.
3. Enable **Forms** in the Netlify UI. The `contact` form is detected automatically from the prerendered HTML. Add an email notification under *Forms → Notifications*.
4. **Rebuild on publish:** create a build hook (*Site configuration → Build & deploy → Build hooks*). Then add a webhook in Sanity (*manage.sanity.io → API → Webhooks*) that sends a POST to that URL on create, update and delete, for example with the filter `_type in ["coffee", "siteSettings", "homePage", "aboutPage", "coffeeIndexPage", "contactPage"]`.

## Trade-offs

- **No client-side navigation.** Each click loads a full page. The pages are 6 to 8 KB of compressed HTML, so this is fast. Adding interactive features later means turning off `features.noScripts` for those routes and allowing their scripts in the CSP.
- **Content changes need a rebuild.** The build hook makes publishing automatic. A full build takes well under a minute.
- **Fonts are downloaded from Google Fonts at build time.** Visitors only ever load them from the site's own domain.
